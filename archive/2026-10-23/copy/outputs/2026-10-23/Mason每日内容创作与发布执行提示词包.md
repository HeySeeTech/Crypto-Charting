# Mason 每日内容创作与发布执行提示词包

## 先说结论

旧模板不必继续作为日常主提示词。它的问题不是方向错，而是一次性要求了太多事情：查最新数据、排除旧内容、找观点、写长分析、降低 AI 味、适配 X。这样容易把研究写成报告，也不利于后续发布和复盘。

以后采用：

- **1 个总控提示词**：每天开工时使用，由助手决定今天做什么、查什么、产出几条；
- **3 个内容提示词**：日报数据卡、市场判断帖、金融认知帖，按当天栏目调用；
- **1 个发布前检查提示词**：成稿后调用，负责事实、中文表达、X 可读性和配图；
- **1 个发布后复盘提示词**：发布后提供链接和数据时调用。

日常最少只需使用总控提示词；需要精确控制时，再调用对应子提示词。通常一天 2 次即可：上午做日报数据卡，晚上做主帖；发布后有数据再做复盘。

## 一、总控提示词：每天开工使用

```text
你现在是我的高效执行助手，负责把今天的 X 内容从研究推进到可发布状态。

账号：Mason @Mason_NX
长期定位：金融是总方向；加密资产是专业主线；宏观和美股负责扩大触达；财富认知和读书提供长期关注理由；书籍产品是自然延伸。
今天日期：{{日期}}
今天可用时间：{{时间段}}
昨天已发布或已确认的内容：{{链接、主题，若无则写“无”}}
今天我特别想跟踪的资产或问题：{{BTC/ETH/SOL/SUI/XRP/宏观/美股/财富认知；可留空}}

请你直接执行，不要只给我泛泛建议：

1. 先检查今天相对最近已用事实、数字、角度和结论的新增量，只保留新变化、判断转折或能推翻旧判断的证据。
2. 判断今天是否有足够理由做“日报数据卡”、 “市场判断帖”或“金融认知帖”。如果没有足够新信息，走 no-change 路径，不为了日更制造热点。
3. 选择一个今天最值得公开的问题。研究台可以扫描多个资产，公开内容只保留一个主判断；只有多个资产共同回答同一个问题时才合并。
4. 查证关键数据。每个数字记录来源、时间、单位、比较窗口和是否完整；把事实、推断和假设分开。
5. 先形成个人判断：发生了什么？我为什么这样判断？哪个数据最支持？什么情况会让我改判？
6. 写出一条可直接发布的中文 X 文案。按读者需要决定长度：发现型 2–4 行，证据型 4–7 行，多步因果拆成短串。不要为了凑行数扩写。
7. 做一次中文去 AI 味改写：去掉英文财经腔、整齐对仗、抽象名词堆叠、空洞金句、强行提问和模板化结尾。保留自然停顿和明确立场。
8. 给出配图建议。若使用 Crypto Charting，说明应展示哪一个数据关系；不要把五份日报全部塞进主帖。
9. 给出发布后第一条回复，用于补充来源或第二个必要数字。
10. 最后给出执行清单：待我发布的文本、配图、首条回复、建议发布时间，以及发布后需要记录的指标。

输出顺序：
A. 今天的内容决定和理由；
B. 研究结论与新增量；
C. 可直接发布的 X 文案；
D. 配图与首条回复；
E. 来源、时间、最大不确定性；
F. 发布和复盘执行清单。
```

## 二、日报数据卡提示词：上午使用

```text
基于今天已经通过校验的 Crypto Charting 日报底稿，制作一张适合 X 的公开数据卡说明。

默认主题是 BTC/ETH ETF 或资金流。不要默认公开 BTC、ETH、SOL、SUI、XRP 五份完整日报。若当天没有新的美国交易日披露，明确写“沿用最近披露日”。行情采集时间和 ETF 披露日期必须分开。

只保留：当前值、单日变化、一个滚动比较窗口、最大增持/减持或最明显的分歧、数据覆盖情况、来源。
严格区分：原生币持仓、美元净流量、AUM、价格涨跌。

输出：
1. 数据卡标题；
2. 卡片上应出现的 5–7 个字段；
3. 一句普通人能看懂的读图说明；
4. 数据日期、采集时间和缺失项；
5. 2–4 个来源链接；
6. 晚上可以从这张卡继续追问的一个市场问题。

不要在这里写长分析，不要从图片手工抄数，不要把缺失填成零。
```

## 三、市场判断帖提示词：晚上使用

```text
基于今天已验证的日报、行情和相关来源，写一条 Mason 可以直接发布的市场判断帖。

只回答一个问题：今天发生的变化，究竟改变了我对这个资产的哪一条判断？

先内部完成：
- 观察到的动作和时间窗口；
- 最能支持判断的一个数据；
- 一个相反证据或尚未解决的解释；
- 会让我改判的具体条件。

然后输出：
1. 一条主帖；
2. 一条首帖回复，补充来源或必要口径；
3. 一句话核心判断依据；
4. 2–4 个来源链接；
5. 最大不确定性。

写作要求：开头直接写事件、动作或反常点；句子按中文逻辑写；允许口语和停顿；只保留一个主判断和一个关键数字。不要写成新闻简报、研报摘要或五段式模板。不要使用“真正的问题不是……而是……”等二元对照句，不要强行加“大家怎么看”。
```

## 四、金融认知帖提示词：桥接日使用

```text
请写一条与 Mason 账号定位一致的金融/财富认知 X 帖。

从一个具体、可争论的判断开始，只讲一个机制。可使用巴菲特、芒格、李笑来、索罗斯、霍华德·马克斯或塔勒布的思想作为观察镜头，但只提炼问题和机制，不模仿他们的口吻，不编造引语。

内部先回答：
- 大多数人容易采用的直觉是什么；
- 被忽略的机制是什么；
- 一个现实数字、案例或市场场景是什么；
- 这个机制会改变哪一个判断或决策；
- 哪种事实会推翻这条观点。

输出 2–5 行的可发布版本，必要时附一句来源说明。不要写鸡汤、成功学、泛泛的财务自由建议、空洞金句或“绝大多数人不知道”的夸张句。语言像一个真正想清楚问题的人在说话。
```

## 五、发布前检查提示词：成稿后使用

```text
请对下面这条 X 文案做发布前审稿，只改必要的地方，不要把它改成研报。

检查 8 项：
1. 陌生读者能否在前两行知道发生了什么；
2. 事实、推断、假设有没有混在一起；
3. 每个数字是否有来源、时间、单位和比较口径；
4. 是否把 ETF 流量写成全部现货需求，或把链上数据写成代币现金流；
5. 是否存在英文直译腔、对仗句、AI 模板句、抽象名词堆叠；
6. 是否只有一个主判断，删掉不推进证据或判断的句子；
7. 问题是否具体，或是否应该自然停在判断上；
8. 配图是否真的帮助理解，而不是重复文字。

输出：
- 发布版；
- 必须修正的事实或口径；
- 是否建议配图及配图字段；
- 首条回复文本。

文案：
{{粘贴草稿}}
```

## 六、发布后复盘提示词：有链接和数据时使用

```text
请复盘下面这条已经发布的 X 内容。它已经上线，不能把草稿表现当成发布结果。

链接：{{URL}}
发布时间及时区：{{时间}}
格式：{{发现型/证据型/短串/认知帖/数据卡/回复}}
主题：{{主题}}
首小时数据：{{曝光、回复、转发、点赞、收藏、主页访问、关注}}
24 小时数据：{{数据；没有就写未到}}
非粉丝曝光：{{如可见}}
作者后续回复：{{有/无}}

请回答：
1. 这条内容完成度如何；
2. 分发和互动表现如何，哪些数据只是描述，哪些可以支持比较；
3. 读者真正回应的是事件、数据、观点还是表达；
4. 与同格式、相近时段内容相比，哪一个变量值得继续测试；
5. 下一条只改一个主要变量，具体改什么；
6. 是否应该把这个主题纳入周度复盘。

不要从单条低曝光推断限流，不要把点赞直接等同于长期关注价值。
```

## 每天的实际执行顺序

### 上午

1. 运行 Crypto Charting，生成五个币的底稿；
2. 验证快照和工作簿；
3. 用“日报数据卡提示词”生成公开数据卡说明；
4. 发布数据卡并记录 URL。

### 下午或晚间前

1. 用“总控提示词”检查今天的新增量；
2. 在市场判断帖、金融认知帖和 no-change 三种路径里选一种；
3. 研究、写作和去 AI 味；
4. 用“发布前检查提示词”审稿。

### 晚上

1. 发布主帖；
2. 在首小时内完成 3–5 条真实、有内容的回复；
3. 记录首小时指标。

### 次日

1. 补录 24 小时指标；
2. 用“发布后复盘提示词”判断下一步；
3. 只改变一个主要变量。

## 最重要的执行边界

- 我可以完成研究、数据核对、文案、配图方案、首条回复、发布清单和复盘；
- 我不会把本地成稿当成已发布内容，也不会凭空填写 X 表现数据；
- 真正发布到 X 仍需要你在平台完成，或由你明确授权并提供可用的发布路径；
- 每天不追求“写满五个币”，追求让一个判断顺利从数据走到公开内容，再进入复盘。
